# Тема, нод-граф и плейбэк-контролы

## Тема и стилизация (путь Meshroom)

- `Utils/Colors.qml` — `pragma Singleton`, фиксирует hex-палитру (тёмная, Grafana-подобная:
  тёмно-серый/угольный фон, акцентный цвет для активных элементов, отдельная шкала для статусов
  узлов графа: idle/running/error/done, и отдельная — для статуса `ChunkSource`:
  connected/buffering/degraded/error).
- `Utils/Theme.qml` — отступы (`spacing`, `margin`), радиусы скругления, толщины линий,
  типографика (единый `font.family`, размеры заголовков/подписей).
- Базовый стиль контролов — `Basic` (`QT_QUICK_CONTROLS_STYLE=Basic` или `Style { }` в `qmldir`).
  Переопределяются точечно только те контролы, что реально видны и часто используются (слайдеры
  параметров нод, скроллбары, панели, статус-бар, плейбэк-контролы) — не весь набор Controls 2
  сразу.
- Регистрация переопределений — через `Controls/qmldir`, чтобы `import Controls 1.0` перекрывал
  стандартные `QtQuick.Controls` типы с тем же именем, как это сделано у Meshroom.

## Нод-граф

- Модель графа — Python-класс на `QAbstractItemModel`, узел = запись с ролями `nodeType`,
  `status`, `position`, `params`. Рёбра — отдельная модель связей source/target port.
- `GraphEditor/Node.qml` отображает узел, читая статус для перекраски рамки (running — анимация,
  error — красная рамка с иконкой). Вся расчётная логика статуса — в Python-контроллере графа,
  QML только визуализирует состояние.
- Взаимодействие (drag, connect, delete) эмитит сигналы в Python-модель; QML не хранит
  собственное «состояние правды» о графе — модель Python остаётся единственным источником истины.
- Оверлей параметров узла (полноценный custom widget над графом) — реализуется как QML
  `Popup`/`Drawer`, привязанный к выбранному узлу через биндинг `selectedNode.params`.
- Узлы, вычисления которых выполняются удалённо (Selectel/Cluster), визуально помечаются иконкой
  источника (`ConnectionBadge`), но логика узла не зависит от того, где физически идёт расчёт —
  это скрыто за `ChunkSource`/backend-контроллером конкретной ноды.

## Плейбэк-контролы (`PlaybackControls.qml`)

- Биндится напрямую к `PlaybackController` (Python, см. `skills/gpu-interop`): `play/pause`,
  `seek(timestep)`, `speed`, `decimationStride` — простые свойства и слоты, без бизнес-логики в
  QML.
- Индикатор `buffering`/`degraded` (канал не успевает) — читает `playbackController.state` (enum),
  не пытается сам вычислять, достаточно ли пропускной способности сети.
- Слайдер децимации ограничен диапазоном, который возвращает `chunkSource.capabilities()` — для
  Local диапазон шире (лучше GPU), для Selectel/Cluster — уже, в зависимости от замера сети.

## Финальная проверка перед PR по UI-слою

- Ни один `.qml`-файл не содержит вычислений над массивами данных.
- Все новые контролы зарегистрированы в `qmldir` соответствующего модуля.
- `qmllint` проходит без предупреждений.
- Цвета и отступы взяты из `Colors.qml`/`Theme.qml`, не хардкожены в компоненте.
- Тяжёлые операции при клике/драге делегированы в Python-слот, а не выполняются в JS-теле QML.
- UI корректно отображает состояние `ChunkSource` (idle/connected/buffering/error) без блокировки
  остального интерфейса при деградации канала.
