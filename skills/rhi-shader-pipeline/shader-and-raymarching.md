# Шейдерная дисциплина, raymarching и адаптивный LOD

## Шейдерная дисциплина

1. Исходники хранятся в `shaders/` рядом с версией GLSL для целевых профилей (`100 es`, `120`,
   `150` — минимум для покрытия десктоп OpenGL и совместимости с RHI-транспиляцией).
2. Компиляция в `.qsb` — отдельный шаг сборки (команда — в `skills/build-and-workflow/SKILL.md`),
   выполняется локально перед запуском и обязательно в CI перед сборкой дистрибутива.
3. **Runtime-компиляция допустима только в dev-режиме** (флаг `--dev-shaders`), чтобы иметь
   hot-reload при правке `.frag` без перезапуска Python-процесса. В продакшен-сборке — только
   заранее скомпилированные `.qsb`.
4. Именование файлов: `<назначение>.<stage>.glsl`, например `wavefield_raymarch.frag.glsl`,
   `fullscreen_quad.vert.glsl`. Скомпилированный артефакт — `build/shaders/<имя>.qsb`.

## Raymarching волнового поля (voxel grid)

- Данные — регулярная 3D-сетка (структурированный voxel grid), не point cloud.
- 3D-текстура (`QRhiTexture.ThreeDimensional`) хранит амплитуду/фазу поля на текущий timestep.
  Рекомендуемый формат — `R16F` (компромисс память/точность для визуализации; расчёты остаются в
  float32/64 на стороне CUDA, в текстуру пишется только визуализируемое значение).
- Фрагментный шейдер выполняет raymarching через объём: на каждом шаге луча — сэмплирование
  3D-текстуры (`texture3D`/`sampler3D`), применение transfer function (1D LUT-текстура: амплитуда/
  фаза → цвет+прозрачность), композитинг front-to-back с ранним выходом (`early ray termination`)
  при накоплении непрозрачности выше порога — существенно снижает число сэмплов на плотных участках.
- Параметры шейдера, управляемые пользователем, передаются через uniform-буфер:
  - `stepCount`/`sampleStride` — шаг луча вдоль направления взгляда, не литеральные точки данных.
  - `decimationStride` — шаг прореживания 3D-сетки при выборке (используется совместно с
    `ChunkRequest.decimation_stride`, см. `skills/gpu-interop`).
  - `timestepIndex` — какой временной срез показывать (перемотка).
  - `opacityScale`, `colorLutOffset` — визуальная плотность и смещение по transfer function.
- Скорость воспроизведения регулируется частотой обновления `timestepIndex` в Python
  (`PlaybackController`), не через QML `Timer`/анимацию — таймер в Python управляет запросом
  следующего чанка через `ChunkSource` и обновлением GPU-ресурса.

## Адаптивный LOD под разное железо

Приложение работает и на слабом ноутбуке, и с данными из облака/кластера — шейдер должен
поддерживать явный уровень детализации без пересборки:

- `maxStepCount` — верхняя граница числа шагов луча, задаётся из Python на основе замера кадровой
  частоты за последние N кадров (простой адаптивный контроллер: если средний frame time превышает
  целевой — уменьшить `stepCount`/увеличить `decimationStride`, и наоборот).
- Профилирование через `QRhiProfiler`/GPU-таймеры RHI (`cb.debugMarkBegin/End`) — для выявления,
  сколько времени уходит на raymarching-проход конкретно, отдельно от остального UI.

## 2D-графики как частный случай

- Тот же `QQuickRhiItem`/шейдерный подход, но: 2D-текстура (`R16F`/`RGBA8`) вместо 3D, шейдер без
  raymarching — прямое сэмплирование с colormap (аналог 1D/2D LUT), направление обхода — одна ось
  (время или глубина), а не полный объёмный проход.
- Примеры компонентов: `SeismogramView.qml`+`SeismogramRenderer` (амплитуда по трассам/времени),
  `SliceView.qml` (срез 3D-объёма по произвольной плоскости — тот же 3D-текстурный ресурс, что и у
  `WavefieldVolumeItem`, но фрагментный шейдер без марша, одно сэмплирование на пиксель).
- Общий код (управление uniform-буфером transfer function, LUT-текстура, ресайз, регистрация в
  interop) выносится в общий mixin/базовый класс `RhiVisualizationRendererBase`, чтобы не
  дублировать между 2D и 3D рендерерами.

## Финальная проверка перед PR по шейдерам

- Каждый изменённый `.glsl` имеет пересобранный `.qsb` в том же коммите.
- Новый uniform добавлен и в шейдер, и в Python-структуру буфера синхронно (порядок полей совпадает).
- Проверена работа на минимальном профиле (`100 es`) — не только на десктопном GLSL.
- Нет блокирующих `glFinish`/синхронных readback в `render()`.
- Адаптивный LOD (`maxStepCount`/`decimationStride`) протестирован на симуляции слабого GPU
  (искусственное ограничение частоты кадров), не только на разработческой машине.
