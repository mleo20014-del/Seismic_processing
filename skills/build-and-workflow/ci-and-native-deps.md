# CI-пайплайн и изоляция native-зависимостей

## Изоляция нативных зависимостей

Единственная native-компилируемая зависимость проекта — `pycuda` (устанавливается через pip,
компилируется под целевой CUDA toolkit при установке). Правила изоляции:

- `pycuda`/CUDA-interop код живёт исключительно в каталоге `interop/` — никакой другой модуль не
  импортирует `pycuda` напрямую.
- Версия CUDA toolkit фиксируется в `requirements.txt`/`pyproject.toml` явно (не «любая доступная»),
  чтобы избежать несовпадения ABI между PyCUDA и системным CUDA driver на Linux/Windows.
- PySide6 и QML-слой не имеют собственных нативных C++-плагинов, написанных в проекте — весь
  кастомный рендер идёт через `QQuickRhiItem` на чистом Python API.
- Сетевые `ChunkSource` (Selectel/Cluster) зависят только от чистого Python (`websockets`/`aiohttp`),
  без дополнительных native-библиотек — единственное исключение — опциональный `blosc`/`zstd` для
  сжатия чанков, оба имеют готовые wheel-пакеты под Linux/Windows без локальной компиляции.

## CI-пайплайн (минимальный набор шагов)

```bash
# 1. Установка зависимостей (закреплённые версии)
pip install -r requirements.txt

# 2. Компиляция всех шейдеров
python scripts/build_shaders.py

# 3. Статический анализ
black --check . && ruff check . && qmllint ui/qml/**/*.qml

# 4. Тесты (мок CUDA-слоя и мок сетевых ChunkSource для раннеров без GPU/сети)
pytest -m "not gpu and not network"     # быстрые тесты
pytest -m "gpu"                          # только на self-hosted раннере с GPU
pytest -m "network"                      # только при доступе к тестовому Selectel/Cluster эндпоинту

# 5. Бенчмарк сетевых источников (не блокирует CI, публикует отчёт как артефакт)
python scripts/bench_chunk_source.py --chunk-source=selectel --duration=30 --output=bench_report.json
```

Не добавлять шаги, дублирующие этот список (например, повторный лишний прогон линтера в отдельном
шаге) — расширять пайплайн только по конкретному новому требованию.

## Dev-цикл (ежедневная работа)

1. Правка `.qml` → мгновенный `pyside6-qml path/to/File.qml` для изоляции визуального компонента
   без запуска всего приложения и без пересборки Python.
2. Правка `.frag`/`.vert` → запуск в dev-режиме с флагом runtime-компиляции шейдера (см.
   `skills/rhi-shader-pipeline/references/shader-and-raymarching.md`, раздел «Шейдерная дисциплина»)
   — избегаем ручного пересобирания `.qsb` при каждой правке одной строки шейдера.
3. Перед коммитом — обязательная финальная компиляция всех тронутых шейдеров в `.qsb` и `qmllint`
   по изменённым `.qml`.
4. Проверка на всех трёх `ChunkSource` перед PR, если изменение затрагивает playback/interop-слой:

```bash
python -m app.main --chunk-source=local
python -m app.main --chunk-source=selectel --ws-endpoint=wss://staging.selectel.example/wavefield
```

Cluster-источник тестируется отдельно, при наличии доступа к тестовому эндпоинту компании.

## Чек-лист для нового участника/агента в проекте

- Прочитан `AGENTS.md` целиком, архитектурные решения не пересматриваются без явного запроса.
- Локально работает `pyside6-qml` на тестовом `.qml`-файле.
- Локально успешно выполняется `python scripts/build_shaders.py`.
- Понятна граница ответственности между четырьмя skill-файлами; новый код кладётся в
  соответствующий модуль, а не смешивается (например, CUDA-код не появляется в `ui/qml`-биндингах).
- Понятно, как переключить приложение между `local`/`selectel`/`cluster` конфигами без изменения кода.
