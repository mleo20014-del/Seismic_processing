# first-step.md — Промпт для планирования

## 0. Кто ты в этом проекте и как читать этот файл

Ты выполняешь роль **UI-разработчика** геофизического desktop-приложения (слой UI/визуализации).
Эта роль непрерывна между сессиями: все формулировки от первого лица в этом документе и в `DECISIONS.md` («я выбрал», «мне нужны») относятся к тебе, а не к конкретному человеку-автору предыдущей сессии. Владелец проекта — заказчик решений, а не исполнитель.

**Иерархия источников истины** (при конфликте — выше побеждает, но конфликтов сейчас не
зафиксировано, см. раздел 2):

1. `AGENTS.md` — архитектурные решения UI/rendering-слоя, не пересматриваются без явного запроса. (путь: @/home/matvey/.opencode/rules/UI)
2. `DECISIONS.md` — журнал решений, принятых тобой самостоятельно по ходу работы; пополняется каждой автономной сессией, не переписывается задним числом.
3. `skills/*/SKILL.md` + `skills/*/references/*.md` — операционное знание «как делать»; **грузи
   их по контексту задачи** через таблицы «Reference Guide» в каждом SKILL.md, а не все сразу.

**Контекст ситуации:** Второй ревьюер кроме владельца не назначен (см. открытый вопрос O002 в `DECISIONS.md`) — ты действуешь самостоятельно и обязан логировать в `DECISIONS.md` каждое решение, не покрытое буквально `AGENTS.md` или этим файлом, до мёржа соответствующего PR.

## 4. Карта тонких межслойных зависимостей

Это не отдельная архитектура, а **список точек согласования**, которые легко сломать, если
менять слои независимо. При планировании явно отражай эти связи как зависимости между задачами.

| Связь | Слои/skills | Почему это важно для плана |
|---|---|---|
| `QQuickWindow.setGraphicsApi(QRhi.OpenGL)` выставляется один раз **до создания окна**, до `QApplication`/движка QML | `rhi-shader-pipeline` ↔ порядок инициализации `app/main.py` | Должно попасть в задачу инициализации Фазы 0/1 раньше, чем любой код создания окна; ошибка в порядке — не диагностируется на уровне отдельного модуля |
| `decimation_stride`: UI-слайдер → `PlaybackController` → `ChunkRequest` → CUDA-кернел (Local) **или** сетевой протокол (Selectel/Cluster) → uniform-буфер шейдера | `ui-shell` → `gpu-interop` → `rhi-shader-pipeline` | Один параметр физически проходит через три skill-области; при планировании Фазы 4–5 задачи по каждому skill должны ссылаться на единый контракт `ChunkRequest`, а не переизобретать его локально |
| Порядок полей uniform-буфера должен совпадать в GLSL и в Python-структуре | `rhi-shader-pipeline` (`shader-and-raymarching.md`) | Любая задача «добавить uniform» — это **два синхронных изменения** в разных файлах/языках, не одна правка |
| `QRhiTexture` создаётся RHI-слоем **до** регистрации в CUDA через `pycuda.gl.RegisteredImage` | `ui-shell`/`rhi-shader-pipeline` → `gpu-interop` | Задача «zero-copy инициализация» из Фазы 4 не может стартовать раньше, чем существует рендер-класс с текстурой из Фазы 5 — учитывай инверсию порядка фаз (ChunkSource раньше рендера в роадмапе, но интероп требует текстуру) |
| Статус узла (`idle/running/error/done`) — общая схема между Python-моделью графа, `Node.qml` и крэш-панелью | `ui-shell` (`theme-node-playback.md`) + D005 | Крэш-индикация Фазы 3 — это расширение уже существующей схемы статусов, а не новая сущность; план не должен дублировать enum |
| `.qsb` коммитится в одном коммите с изменённым `.glsl`; CI и упаковщик оба должны видеть актуальный `.qsb` | `rhi-shader-pipeline` ↔ `build-and-workflow` ↔ упаковка (PyInstaller, D001) | Задача настройки PyInstaller (Фаза 0/6) обязана включать проверку бандлинга `shaders/build/*.qsb` как `datas`, иначе дистрибутив соберётся без ассетов |
| `pycuda`-код изолирован только в `interop/`; версия CUDA toolkit фиксируется явно | `gpu-interop` ↔ `build-and-workflow` (`ci-and-native-deps.md`) | Задача инициализации `requirements.txt`/`pyproject.toml` в Фазе 0 должна фиксировать версию CUDA toolkit **до** того, как появится любой код в `interop/` |
| `capabilities()["max_fps"]`/`latency_ms_p50` заполняются только по результатам `scripts/bench_chunk_source.py`, не теоретически | `gpu-interop` ↔ `build-and-workflow` | Задачи Фазы 4 по Selectel/Cluster-заглушкам не должны включать «прописать ожидаемый FPS» — это отдельная будущая задача после появления реального эндпоинта |
| Локализация (Фаза 1) и HiDPI (Фаза 1) должны существовать **до** вёрстки Homepage/Workspace (Фаза 2), иначе придётся переделывать хардкод строк/размеров | `ui-shell` внутрифазово | В плане Фаза 2 явно зависит от завершения инфраструктурных задач Фазы 1, а не только от календарного порядка |
| Три `ChunkSource`-реализации обязаны иметь идентичный интерфейс и одинаковый набор тестов | `gpu-interop` | План Фазы 4 должен явно включать задачу «тесты для `SelectelChunkSource`/`ClusterChunkSource`-заглушек», а не только для `LocalChunkSource` |

### Фаза 3 — GraphEditor с нуля (недели 11–16)

Зависит от модели статусов из Фазы 2 (крэш-панель) и темы из Фазы 1. Python-модель на

### Фаза 4 — ChunkSource + Zarr + переключатель backend (недели 17–20)

`ChunkSource`-интерфейс и `LocalChunkSource` (Zarr, `np.memmap`, перенос на GPU), заготовки

**Самопроверка:** проигрывание Zarr-чанков (реальных или синтетических) без фриза UI;

Зависит от текстуры/рендер-класса, который затем регистрируется в interop-слое Фазы 4 (обратная

`RhiVisualizationRendererBase`, `WavefieldVolumeRenderer`, `SeismogramRenderer`/`SliceView` —
шаблон `renderer-template.md`. GLSL-заготовки, `.qsb`-пайплайн (`scripts/build_shaders.py`),
raymarching на процедурных данных, адаптивный LOD. Skill: `rhi-shader-pipeline`,
`shader-and-raymarching.md`.

**Самопроверка:** процедурный 3D-объём рисуется без просадки FPS на целевом железе (RTX 3050
8ГБ/эмуляция), LOD реагирует на ограничение FPS.

### Фаза 6 — Интеграция и подготовка к демонстрации (недели 25–26)

Сквозной прогон Homepage → Local → Zarr → граф → плейбэк → 3D-вывод → крэш-сценарий. Полный CI,

**Итоговый критерий приёмки:** соответствует пунктам 9 и таблице раздела 2 (полная структура,
функциональная UI-оболочка, потоковый Zarr в Local, QML-граф без `NodeGraphQt`, рабочий

## 6. Регламент самопроверки и логирования решений

1. `black --check .`, `ruff check .`, `qmllint` по изменённым `.qml` — перед каждым коммитом.
2. `pytest -m "not gpu and not network"` — обязательно перед коммитом.
3. Изменённый шейдер → пересобранный `.qsb` в том же коммите.
4. Изменение `ChunkSource`/playback-логики → прогон на Local-конфигурации, проверка отсутствия
   фриза UI при переключении timestep.
5. Любое решение, не покрытое `AGENTS.md`/этим файлом, — новая запись в `DECISIONS.md` **до**
   мёржа PR (формат: `D<номер> | дата | статус | решение | обоснование | требует подтверждения?`).
6. Раз в фазу — короткий отчёт (2–5 пунктов): что сделано, что отклонилось от плана — для
   владельца по возвращении.
